## 2. The print agent
- Polls every **3 s** by default (floor 2 s); an org admin can change it per print server on that server's page ("How fast it picks up jobs"; stored in `agents.poll_interval_seconds`, handed back in the heartbeat). The old 60 s floor existed only to save Vercel CPU.
- **Printer feedback is ON by default** (`PRINTIO_PRINTER_FEEDBACK=false` switches it off). After sending a raw-port job it reads the printer's page counter before and checks it a few times after (first ~10 s + 0.5 s/page, then every 10-20 s); confirmed when the counter rose by at least the job's pages: "Printer confirmed N of N pages". Otherwise "Sent to the printer" (never a false failure). Unique PJL job name per job; never auto-resends; the agent's own probe stays off the printer meanwhile. Proven with a script on the real printer; **not yet run end to end through the real agent**. Booklet expected counts (imposed pages x copies) are unmeasured.
- Raw sends no longer fail with "printer did not confirm": after all bytes are flushed the job counts as sent (the Kyocera never closes the connection by itself).

## 3. Printer facts (TASKalfa MZ8500i, 192.168.100.168) - details in `docs/kyocera-raw-print.md`
- Proven by real prints: duplex long/short edge, copies (QTY), staple top-left / top-right / bottom-left, **dual staple left (`STAPLEOPTION=TWO FINISH=STAPLE`, needs at least 2 sheets)**, **3-hole punch (`FINISH=KPUNCH`)**, `MEDIATYPE=PLAIN`, booklets left and right (`DUPLEX=ON BINDING=SHORTEDGE OUTBIN=KBOOKLET FINISH=KFOLD`; never `KREVERSEFOLD`), `PAPER=LEDGER`.
- The printer lists what it accepts (read with `tools/raw-print/pjl-inquire.mjs`): 39 `PAPER` sizes, 28 `MEDIATYPE` values, 16 `OUTBIN` values, punch (main 3-hole, sub 2-hole). **Only Letter and Ledger are loaded**, so only those are advertised: sending a size or type nothing is loaded for makes the printer wait for paper and blocks everyone. Trays: TRAY1 Letter long-edge for booklets, TRAY2 Ledger, TRAY3/4 regular Letter, bypass = cardstock.
- **Unresolved:** routing to the bypass tray or a paper type. A `MEDIATYPE=CARDSTOCK` job never came out (printer showed no error), and the official driver puts tray/type inside the page data (PCL XL), not in PJL, so a PDF job cannot name a tray the same way. Ask the owner how the bypass is configured before more tests.
- What the printer says on port 9100 (measured): `JOB START` message only on an open connection; `PAGE n` counts printed **pages (sides)**; the `JOB END` message (with the job name and PAGES) is pushed only to a connection that is open at that moment (short checks usually miss it); a second connection is ignored while a job connection is open; `INFO PAGECOUNT` works any time and rises by exactly the pages printed; the PJL status "Processing..." partly comes from our own connections (do not trust it as "busy"); the printer remembers `USTATUS` settings, so never leave `PAGE=ON`/`TIMED` set. Every connection may appear as an entry in the printer's own job log, so ask sparingly.
- IPP: the printer answers `Get-Jobs` on https port 443 `/ipp/print`, but only for jobs submitted over IPP, not raw-port jobs.
- Never send a document that could change the printer's settings (PJL escape sequences are rejected, see SECURITY.md).

## 4. Hebrew / fonts (a Hebrew PDF printed with most small Hebrew missing)
- Verified by 55 tests (`apps/web/lib/pdf/hebrew-fidelity.test.ts`): none of Printio's steps (preflight, sanitize, page range, booklet padding + imposition, stamp) changes non-Latin text, fonts or ToUnicode maps.
- Safeguard in the pipeline (`lib/pdf/text-fidelity.ts`): if the non-Latin text of a derived PDF differs from the original, the job is HELD with a plain reason and nothing prints; it fails open (an error or timeout never blocks a job).
- Three real-printer test sheets (pdf-lib subset font, full font, Edge-printed David) all printed correctly, so ordinary TrueType Hebrew is fine. The original damaged PDF (Tanya_Study_Calendar_Vov_Zayin.pdf, jobs 152/153) was never inspected: likely a source-PDF or unusual-font problem (Type 3 / odd CID maps). Use the new **job viewer** (below) to open the original and the "as sent" PDF and see where the text was already missing. A real fix, if needed, would convert such pages (outlines or images) before sending.

## 5. Features added this session (all in `docs/FEATURES.md`)
- Print dialog advertises Letter + Ledger only (11x17 plain jobs are stored as paper_size "tabloid", agent sends `PAPER=LEDGER`); devices that added the printer earlier must remove and re-add it. A **Beta note** on the Devices page says so.
- Large PDFs upload straight from the browser to Supabase storage (over 3.5 MB); the 4.5 MB limit was Vercel's and does not exist on the PC, but the direct upload stays. The multi-file booklet builder still posts through the server.
- **Job viewer**: the sender and the org's admins/approvers can open the stored PDF from the job page ("View original file", "View as sent to the printer") until retention or the sender deletes it (`GET /jobs/<id>/file?which=original|sent`). Platform super admin gets nothing just for being one.
- Print server page: opens straight from the menu when there is one server; floating, minimisable update notification; speed setting.
- Privacy and terms pages (`/privacy`, `/terms`). **Privacy model (owner decision):** org admins can open every file of their organization (including print-dialog jobs); the platform owner does not see orgs' PDFs through the app (the page admits the operator could technically reach storage).
- **Google sign-in is built but shows "Coming soon"** until `NEXT_PUBLIC_GOOGLE_SIGNIN=1` is set at build time AND the Google provider is enabled in Supabase AND the Google consent screen is published to production (so any Google account can sign in; access still needs an invite or an allowed domain). The setup script keeps that variable if present.
- Many Vercel-CPU fixes (session lookup cached per request, proxy skips auth for cookie-less requests, calmer refreshes, bounded admin queries, leaner agent API, hot-query indexes); they are harmless on the PC.
- A same-site check bug behind the tunnel is fixed (`lib/http/public-origin.ts`): the server sees plain http, so Origin checks and redirects use the forwarded https origin.
