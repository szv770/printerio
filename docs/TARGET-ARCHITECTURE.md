# Target architecture (decided with the owner 2026-11-15) - a plan, nothing here is built yet

Read this before touching hosting, the agent/gateway link, uploads, updates or the library. It replaces the older idea that the owner's PC
runs the whole website (`docs/STATE-2026-11-01.md` section 1 describes how it runs TODAY; that stays until phase 6 below).

## 1. The rules (owner's words, tidied)
1. **Cloudflare only serves the website and forwards visitors.** No heavy work on it: no PDF building, no layout, no checking, no fetching of
   outside sites. Heavy work runs on a print server.
2. **Supabase** holds logins and the shared data. **Each school's print server** does printing, the print-dialog (IPP) gateway, PDF work and
   keeps that school's files.
3. If a school's print server is offline, the website still works (login, queue, admin) and anything needing the server says plainly:
   "Your print server is offline, so I can't do that right now."
4. Other schools can add their own servers by themselves, safely. Printio's code stays in a **private** repo; a school never gets a GitHub key.
5. Stay inside free tiers as long as honestly possible, watch usage, and move to a paid plan before a limit hurts a school.

## 2. Decisions made (owner answers, 2026-11-15)
| Question | Decision |
|---|---|
| Scale to plan for | 5-15 schools, about 1,000 people in the next year |
| Where PDFs live | On each school's own server. Browser uploads straight to that school's server through its Cloudflare tunnel. No cloud file storage, no download fees. Server off = uploading and viewing say "server offline" |
| Supabase | Free for now with a tiny daily keep-alive; **Pro ($25/month: daily backups, no pausing) before the SECOND school joins** (owner, 2026-11-15, after the design review). Until then: a weekly copy of the data and one tested restore |
| How servers talk to the cloud | Straight to Supabase with live push (Realtime), never through the website. Per-server credentials; a school's server can only see its own school |
| Deploys | GitHub builds and deploys to Cloudflare only when a change is merged (no preview builds); one limited Cloudflare key stored as a GitHub secret |
| School tunnels | Printio creates one Cloudflare tunnel + address per school automatically when the school clicks "Add a print server" (owner kept this on 2026-11-15 although the design review advised creating them by hand). To limit the danger (an account-wide key that could touch the live site's tunnel or DNS): the school tunnels live in a **separate, free Cloudflare account with its own domain**, never in the account that runs the live site; the key is Tunnel-and-DNS-only for that account, held only by the one cloud function that needs it, used only by the platform owner's approval step; this is built LAST (phase I), after everything else works. Until then tunnels are made by hand |
| Shared lists and daily-study text | The owner's own server fetches a week ahead on a schedule and saves to Supabase; schools only read the saved copy. Library PDFs are fetched by whichever school's server is building the booklet, at that moment, and are not stored in the cloud |
| Fonts for other schools | Everyone gets the free-licence fonts (Ezra SIL, David Libre, EB Garamond, Source Serif 4, Libre Baskerville, and more open fonts later). A school that wants a specific licensed font (for example SBL Hebrew, about $5) buys it and uploads it on its own Admin -> Fonts page (already built). The owner's licensed fonts are never shipped to schools and never put in git; they are uploaded privately for the owner's own organization (so the repo can be private) |
| Booklets | **Each school builds its own booklets on its own server** (owner, 2026-11-15: sharing or pushing pre-built booklets between schools was dropped; it "is backwards"). Nothing about booklets is built centrally or pushed anywhere |
| Domain (owner, 2026-11-15) | **printio.app is the project's domain; szvtech.org is retired for this project.** Today everyone uses the PC site on `beta.printio.app`, which stays the STABLE site. The plain **`printio.app` address is the TEST site** (owner's idea: nobody uses it, so a problem there costs nothing); the Cloudflare-hosted version is tried there first. Caution: a test site on the same Supabase database as beta could write bad data that beta users see, so the test site uses a **second free Supabase project** (same structure from the migrations, separate data; the free plan allows two active projects). When the test site has run clean for a month, users move to `printio.app` and beta stays as a fallback for a while. The IPP print-dialog gateway currently answers on `*.szvtech.org`; moving it to a printio.app name means every device re-adds the printer once, so bundle that with any other change that needs a re-add. Nothing on the PC, the tunnel or DNS is changed without the owner's explicit yes |
| A school's server is off | Accepted (owner, 2026-11-15): nobody at that school can submit or view files from the website until its server is on; the site says so plainly. Always-on is a condition for a school. Count complaints for a month and revisit |

## 3. What runs where
| Piece | Runs on | Notes |
|---|---|---|
| Pages, login screens, job list, admin screens | Cloudflare (free) | Dynamic requests count against 100,000 a day, 10 ms CPU each, 3 MB compressed bundle ([limits](https://developers.cloudflare.com/workers/platform/limits)). Static files are free |
| Logins, shared data, live push | Supabase | Free: 500 MB database, 5 GB traffic, pauses after a week idle ([pricing](https://supabase.com/pricing)). Today's database: 18 MB; daily study text about 94 KB a day, about 34 MB a year |
| Booklet builder, daily-study layout, page checks, imposition, thumbnails | The school's print server | Becomes "jobs" the server claims (like print jobs today); the website shows progress. |
| Print dialog gateway, agent, files, retention | Print server | Already there; gateway must stop holding the master Supabase key (phase 2) |
| Timed jobs (cleanup, sweeps, keep-alive) | Cloudflare cron or Supabase timers | The PC no longer has to be on |
| Shared daily text and lists | Owner's server, a week ahead | One fetch a day for everyone; schools read the saved text and each builds its own booklets |

## 4. Usage hot spots found in the current code (fix before moving)
- **Agent loop.** Every 3 s the agent makes THREE calls to the website (heartbeat, commands, claimable jobs: `apps/agent/src/orchestrator.ts:847-861`). That is about **86,400 requests a day per server, about 86% of the free daily limit for one school** (measured in the code 2026-11-15; an earlier version of this plan said 28,800, which counted one call). Must go to Supabase directly with push, and the heartbeat slows to 30-60 s.
- **Browser auto-refresh:** home and admin pages refresh every 30 s on any visible tab; the job list and job page every 4 s while a job is active; the print server page every 5-10 s (not 2 s as first written). Realtime already exists for `print_jobs`, `agents` and `remote_commands` (migration 0011) and three pages use it; make polling a slow backstop. Details: `docs/phase0-code-inventory.md`.
- **Heavy libraries in the website bundle** break the 3 MB limit. Measured 2026-11-15 (gzip): the real website as it is = 6.26 MiB with OpenNext and 3.63 MiB with vinext, both over the free 3 MiB; without the PDF and font code = 3.99 MiB (OpenNext) and 1.93 MiB (vinext); also without the icon-image library = 3.21 MiB and 1.04 MiB. So after phase 1 the website fits the free plan only with **vinext**. The PDF/font libraries (pdf-lib, pdfjs, fontkit, base64 fonts) are about 1.7 MB of the compressed size. Details: `docs/phase0-cloudflare-build-trial.md`.
- **Supabase storage (1 GB free)** is avoided by keeping PDFs on the schools' servers.
- **Builds:** Cloudflare free = 3,000 build minutes a month on Workers builds ([limits](https://developers.cloudflare.com/workers/ci-cd/builds/limits-and-pricing/)); GitHub Actions on a private repo = 2,000 free minutes a month ([billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions)) and our checks take about 3 minutes per run. Deploy only on merge; avoid needless pushes.
- Rough estimate to verify in the trial: 1,000 active people may use 20-50% of the daily free request limit. Rule: move to Workers Paid (about $5/month) when daily use passes ~70%, and set an email alert there.
- As understood (not verified): going over a free limit makes requests fail until the next day rather than charging.

## 5. Security model
- **Per-server identity.** Enrolling gives each server its own credential scoped to one school (a Supabase login carrying `org_id` and `agent_id`, enforced by row-level security). The school server never holds the service-role key (the gateway holds it today: `apps/gateway/src/config.ts`). Revocable per server.
- **Add a print server:** admin clicks the button; the cloud creates a one-time code (about 30 minutes, single use, hash stored), creates the school's tunnel and address, and shows one install command. The installer sets up the agent, which generates its own key and enrols with the code. The existing register flow (`docs/agent-api.md`) is the starting point.
- **Updates with no GitHub key:** CI builds and **signs** release bundles and publishes them somewhere public-read and free of download fees. The cloud only points a server at a version (URL + checksum + signature); the agent verifies against a public key built into it, installs, and rolls back on failure. Servers run no git. The cloud can never make a server run arbitrary code. "Update now" then works for every school.
- **Browser to school server uploads:** the cloud mints a short-lived upload token for one school; that school's server checks it (public key) and accepts only that school's users, with size and type limits and CORS for the website only.
- **Biggest new secret:** the Cloudflare key that creates tunnels and addresses. Scope it to the one zone and tunnels only, keep it only in the cloud function that needs it, rotate it, and make each school's tunnel revocable alone.
- **Shared text integrity:** schools only read the shared lists and daily text; only the owner's server writes them (so no school can alter what others read).
- **Fonts:** only free-licence fonts ship to schools; licensed fonts are uploaded privately for the owner's organization only (and by a school for itself). Technical check on the owner's fonts (2026-11-15): no font file forbids embedding or subsetting in a PDF (OT fonts: no restriction set; SBL Hebrew: editable embedding allowed). That flag is not the licence agreement: see section 7.

## 6. Phases (revised 2026-11-15 after the design review: `docs/DESIGN-REVIEW-2026-11-15.md`)
Each phase has a GO gate (what must be true to start the next) and a rollback. Nothing needs the owner's real Cloudflare account until phase E, and even then only a throwaway account with no card. The live site on the owner's PC is not touched until phase H, and stays as the fallback for a month after.

- **A. Safety net.** Two-school isolation tests in CI (one school can never read or change another's data; fails closed when a table is added); a weekly copy of the data and one tested restore (Supabase free has no backups; Pro before the second school). GO: the tests pass in CI and a restore from the copy has been done once. Rollback: n/a (tests and a script).
- **B. Quick wins on the PC.** *Status 2026-11-15: agent and website side built and tested, not yet run on the real PC. Commands now ride in the claimable call (`?commands=1`) and the heartbeat is every 30 s (`PRINTIO_HEARTBEAT_SECONDS`, 0 = old behaviour): about 31,700 requests a day per server instead of 86,400 (63% less); the browser-refresh half is not done.* Fold the agent's three calls into one and slow the heartbeat (about two thirds less traffic); slower browser refresh with Realtime where it already exists. GO: printing unaffected for a week. Rollback: revert the PR. (The framework upgrade stays out of the live branch until the trial; see `docs/PHASE0-FINDINGS.md`.)
- **C. Heavy work becomes server jobs, one feature at a time, each behind a switch.** Order: library and daily-study fetching (a general "server jobs" mechanism with a shared read-through cache in Supabase: the website asks, a server fetches once, everyone shares it; "print server offline" when none is online), then the daily booklet build, then the booklet builder and font inspection, then link import and test print, then preview; finally split `createPrintJob` into "prepare file" (server job) and "create job" (website). GO per feature: works for a week with the switch on. Rollback: switch off, the old path is still there.
- **D. Per-server credentials, narrow.** Servers get no table access, only about six functions that take the school from the `agents` row; one small endpoint swaps today's device secret for a 1-hour token with a dedicated role; revocation is immediate because every function checks the server is active; replace `GATEWAY_SHARED_SECRET` and the master key in the gateway. GO: the owner's own server runs it for two weeks; the two-school tests cover the functions. Rollback: the old routes stay for one release.
- **E. Throwaway Cloudflare trial.** On a free account with no card: real CPU per request logged in (10 ms free limit), the 50-calls-per-request limit, Realtime counts, the key-scoping test (try to delete an unrelated tunnel with the supposedly narrow key), the wildcard address / certificate test with a phone, Windows and Chromebook. GO: numbers recorded and acceptable (or $5 plan chosen).
- **F. Files stay on the school's server.** Browser uploads straight to the school's server through its tunnel (single-use 5-minute tokens, 50 MB limit, no-store). GO: nothing new in Supabase storage. Rollback: back to Supabase storage.
- **G. Signed updates and a second test server** (tunnel made by hand): signing in a separate manually approved step, two built-in public keys, no downgrades, automatic revert, the owner's server updates first and runs 48 hours, a deliberately broken release tried on a VM. GO: the broken-release drill passes.
- **H. Website on Cloudflare under a NEW name** (never move `beta.printio.app`; it stays on the PC as the fallback). The framework upgrade ships here, on the trial branch. GO: a month of both running. Rollback: keep using beta.
- **I. First outside school** (Pro is on; a data agreement is signed; the school's tunnel is made by hand, then the automatic, separately isolated one is built and tried on the second school).
- **J. Retire the PC website** a month after H, only if it ran clean.

**Interim bridge until H/J:** the admin "Update this server" button also rebuilds the website on the PC (`tools/self-host/update-web.ps1`, task `Printio Web Update`, `NEXT_DIST_DIR` in `apps/web/next.config.ts`, the folder pointer in `run-web.ps1`). Delete all of it when the website moves to Cloudflare (phase H, final cleanup in J); see `docs/agent-install.md`.

### Before the owner connects ANY real Cloudflare account
Trials on a throwaway account with no card, against a SECOND Supabase test project (never the live database); two-step sign-in on the real one; the only key ever issued on the real account is deploy-for-this-one-site; website cookies host-only (`__Host-`); the key-scoping and quota tests written down and passed.

- **Print-dialog addresses per school (found by the design review, unverified; owner prefers a redesign over paying about $10 a month, 2026-11-15):** a device is identified today by its address `u-<code>.szvtech.org` (`apps/gateway/src/server.ts`: identity is the Host header, the URL path is ignored). One wildcard DNS record can point at only one school's tunnel, and a second-level wildcard (`*.school.printio.app`) is not covered by the free certificate; Cloudflare's paid add-on that covers it (Advanced Certificate Manager) is about $10 a month on the account (price as remembered, verify). **No-cost redesign to test first (phase E):** one single-level address per school, `school1.printio.app` (one DNS record and one tunnel per school, covered by the free certificate), and the device code moves from the host into the printer address path, for example `https://school1.printio.app/ipp/<code>`; the gateway would read the code from the path (a gateway change; clients accept any path in an IPP address, but this must be proven on the phone, Windows and the Chromebook before it is promised). Devices re-add the printer once (they must anyway, since szvtech.org is retired). If the redesign fails on a platform, the $10 route is the fallback. **Related:** school server hostnames under `printio.app` share the website's registrable domain, so a school server could try to plant cookies for the website; **Decided 2026-11-15 (owner): no second domain; make the website's cookies host-only with the `__Host-` prefix** (a small website change, tested) so no school server can set cookies for the website.
- **Installer defaults:** a fresh install runs the gateway and agent as LocalSystem (full rights); the limited account is a manual script today. Make the limited account the default for every school's installer, and turn on BitLocker.
- **Realtime free limits:** heartbeats into the published `agents` table at 15 servers every 30 s is about 1.3 million messages a month against about 2 million free; use an unpublished heartbeat table and a 60 s backstop.
- **Sign-in email:** Supabase's built-in sender allows only a few emails an hour; check whether a custom sender is set up before more schools sign in.
- **Offboarding runbook** (disable credential, delete tunnel and address, delete or export rows, wipe files) and a stolen-server runbook; I have not verified that every table cascades on delete.
- **Questions for a lawyer or the schools (not legal advice):** student accounts and ages, FERPA/COPPA and state laws, a data agreement naming Supabase and Cloudflare, student names in file names and documents, breach notification, hosting country, deletion when a school leaves, font and study-text licences for other organizations.
- Website cookies become host-only (`__Host-` prefix) so a school server on a printio.app address cannot plant cookies for the website (owner chose this over a second domain, 2026-11-15).
