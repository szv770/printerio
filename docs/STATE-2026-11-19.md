## 4. How to go live safely (in this order)
1. **Look over the screens** (the owner has screenshots of the front page, Help, Print page and admin/teacher look) and say yes.
2. **Database:** apply migrations in order 0054 (security fix), 0055, 0057, 0058, 0059. Each only adds tables/columns or tightens access rules and is re-runnable; check the database after each (the tool asks you to press Allow; it timed out once while nobody was there, nothing was applied). The website is built to tolerate a missing table or column (it treats a failed read as "off"), but that was tested with a stand-in database only.
3. **Merge PR #144** into the default branch `claude/upcoming-large-project-3d2j9p` once CI is green on the head. Check which branch your PC's checkout follows: if it follows another branch, merging alone changes nothing there.
4. **On the PC:** press "Update this server" (pulls the code, installs, restarts the gateway, rebuilds the website through the interim bridge). One-time catch: servers updated by the OLD update code get the new update code on that first press; if it says it could not install, run `docs/hardening/fix-update-permissions.ps1` once.
5. **Leave the new switches off** until the timing run (`docs/PREPARE-BENCH.md`) and the byte comparison on real PDFs are done. Phone presets only appear once the gateway is updated; check the paper-type list on each device (steps in `docs/OWNER-TODO.md`).
6. **Domain:** `u-<code>.printio.app` device addresses do not resolve yet (no wildcard DNS); do not retire `szvtech.org` until every device has been re-added.

Rollback: re-deploy the previous commit through the same Update button path (it fast-forwards only, so use a revert commit on the default branch); the migrations only add things and can be left in place (0054's old policies are in migrations 0006/0009/0034 if ever needed).

## 5. What is untested (say this plainly to anyone)
Nothing here has run on a real print server, a real printer, a real phone, the real database, the live website or Cloudflare. The PDF steps were exercised on generated files only; real-file timings and a byte comparison are still owed (`docs/PREPARE-BENCH.md`). Phone behaviour (paper-type list, sharing a file with Wi-Fi off) needs the owner's device checks.

## 6. Known gaps and follow-ups
- "Print again" does not restore a layout choice (the layout is not stored with a job; touches the money path, needs its own careful batch).
- Border and "first page only" for repeat layouts exist on the server but have no controls.
- Admin menu regroup, first-run setup and one-step school creation wait for the owner's answers (`docs/ADMIN-DASHBOARD-PLAN.md`).
- Cloudflare: React 19.3.1 bump, size guard, real CPU numbers and the 50-subrequest limit (needs a Cloudflare account); legacy PDF code must be deleted to get under the 3 MiB limit. See `docs/SAAS-LAUNCH-PLAN.md`.
- Partnership and scale ideas: `docs/SAAS-IDEAS-AND-PARTNERSHIPS.md`.
- Vercel's red "Account is blocked" on pull requests is noise (Vercel is not used any more).
